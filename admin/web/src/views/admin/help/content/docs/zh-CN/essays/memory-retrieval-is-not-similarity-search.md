# 记忆检索不是相似度检索

**[简体中文](memory-retrieval-is-not-similarity-search.md) · [English](../essays/memory-retrieval-is-not-similarity-search.md) · [返回文档中心](../README.md) · [返回仓库主页](../../README.md)**

打开任何一个 agent 记忆项目的 README，第一段几乎都长一个样：把对话切块、跑嵌入模型、存向量、查询时按余弦距离取最近的那几块。它成为默认做法是有理由的——模型、索引、存储全都有现成件，一个下午就能跑出能演示的东西。我们最初也是这么做的。问题出在你不再问“哪几块长得像这个问题”，而是开始问“记忆到底要来干什么”的时候。

---

## 一、提问和答案，从来就不像同一个东西

举个很常见的场景。问题是：上周二开始，nightly 构建为什么挂了？库里躺着几十条关于构建的记录——状态播报、缓存讨论、CI 时长的来回——以及一句话：`ci: bump toolchain to 1.91 — nightly now dies at link stage`。

答案就是那一句。它跟问题在字面上几乎找不到重合的词；比起那几十条围绕“构建”闲聊的记录，它的话题重叠也算不上突出。按相似度排序，闲聊会赢，那句决定性的话会沉下去，或者干脆浮不上来。

原因很简单：**相似度是对称的。**它衡量的是两段文字在谈同一件事的程度。而提问和答案从来不对称——答案的价值，恰恰在于它包含了问题里没有的那部分。答案越是不像问题，越可能有用。

---

## 二、复读看起来“很像相关”

向量空间是平滑的：措辞差不多的重复内容会挤在一起。这对去重是优点，对排序是隐患。

你自己的历史里从来不缺近似重复：重试日志、隔三差五的状态播报、同一个 bug 在三个会话里各说一遍。而真正稀有的那条例外——只出现过一次的、具体的记录——在向量空间里是个离群点。被说得最多的内容挤掉只出现一次的孤例，这是距离度量的天性。但记忆的全部价值就在那个孤例：你不会记得五十天里部署都正常，只记得出事的那一天。

这件事有一个很朴素的表述：**在几乎所有文档里都出现的词，几乎不携带信息；只在一篇里出现的词，几乎携带全部信息。**重复降低信息量，而相似度把重复当成相关的证据。于是这两个量恰好在记忆最要紧的地方朝相反方向走。

---

## 三、记忆的问题，是事件问题

“我们是什么时候定下这个方案的？”“重试循环是谁引入的？”“出事之后改了什么？”——这才是人真正会问记忆系统的问题。它们是**事件问题**：要有时间、主体、变化。

而一个向量是摊平了时间的话题袋：去年的事故和今天的修复可以贴得极近，谁前谁后完全看不出来。你当然可以在排序外面补一层时间衰减或日期过滤，也应该补；但每补一层，都是在承认核心分数没有回答这个问题。时间、实体、变化是结构性的东西，应该长在索引里，而不是事后撒在距离上。

---

## 四、把模型塞进记忆格式里

向量嵌入还有一个更安静的代价：它让**某个具体的模型成为你记忆格式的一部分**。向量只对生成它的模型有意义。换掉嵌入模型，或者旧模型被服务方下线，昨天的向量就变成没人能读的方言——要么把全部历史重算一遍，要么长期维持两代检索方言并存。一份打算留很多年的笔记，不应该取决于写下它的那天，恰好是哪个模型快照在服役。

对一份强调本地的记忆，这还多两重依赖：写入路径上要有一次模型调用（或者退化成批量队列，更糟——“刚存的”不再等于“刚能搜到”），读取路径上通常也要，还得有个活着的服务。把这些拿掉，剩下的东西简单到可以审计：逐字原文，加一个从你自己的语料里长出来的索引，离线、毫秒级、确定性。

---

## 五、那我们按什么排序

这不是说相似度一无是处，是说它不该做记忆检索的主键。主键应该是**判别力**：这条记录能把“它可能是答案”的胜算推多远，而不是它离问题多近。

判别力可以从你自己的语料里算出来：词的权重来自自适应语料自信息，而不是外部静态词表或预训练先验；同一个问题问两次，回来的是同一批结果；每条排位都能展开成它排在那里的依据——命中了哪些稀有的词、哪个时间窗、哪个实体。**一个能被质问的检索系统，才是能被修好的检索系统。**Rolling Memory 的默认本地检索走的就是这条路：按语料自信息与跨形式确定性对齐排序，不经过向量，也不在检索链路里调用模型。

---

## 六、代价，说清楚

相似度真正的长处是改写：你说“车打不着火”，它能连上“发动机无法起动”。如果记忆的日常工作是翻译，这个长处会很值钱。但你很少改写自己的过去，你只是忘了它。真正要紧的查询锚定在你自己的词汇上——你的仓库名、你的错误码、你的日期，而这恰好是稠密空间最模糊的地方（两个相邻的错误码、两个相邻的端口、相差一周的两个日期），也正是频次算术最清晰的地方。词汇确实漂移的时候，确定性的构词还原和语料级共现能接住大部分。

剩下的那一小撮——完全由比喻构成、跟原文零字面重合的提问——是真实存在的薄尾。我们宁愿知道它有多薄，也不假装它不存在。**每种设计都要在某个地方交税，我们宁愿交在这条薄尾上，而不是每一次写入和每一次读取。**

---

所以：相似度告诉你哪段话*看起来像*你的问题；记忆要告诉你哪条事实*会改变*你的答案。前者是一个下午就能做出来的演示，后者才是产品。如果你 agent 的记忆总是把“被说得最多的版本”端回来，那是距离度量在尽职——而记忆本身失职了。
