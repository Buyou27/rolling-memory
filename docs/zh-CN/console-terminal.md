# Web 控制台内置命令行（终端）

**[简体中文](console-terminal.md) · [English](../console-terminal.md)**

Rolling Memory 的管理后台内置一个轻量命令行工具（面板里的「终端」）：把「记忆引擎正在做什么」的实时流与「手动执行常用命令」放在同一个窗口。你可以实时看到 `recall` 的命中与耗时、最近写入的记忆单元，也可以一键执行 `rmem`（`rolling-memory`）的诊断与维护命令。所有执行都发生在你本机的本地明文金库上，零云端请求。

---

## 1. 打开方式

| 入口 | 位置 |
|---|---|
| 顶栏终端图标（Rolling Memory CLI Terminal） | 管理后台页面顶栏右侧，随时展开/收起 |
| 桌面浮标 | 面板右下角漂浮徽标展开后的终端入口 |
| 记忆总览页 | 运行状态卡片与页脚均提供「打开终端」按钮 |

终端是一个浮动窗口，展开状态在页面间切换时保持不变；有新任务结束时入口会显示未读圆点。

## 2. 界面构成

1. **实时流**：引擎的 `recall` 事件（命中/未命中、命中块数、注入字符数、耗时毫秒）与宿主 Hook 事件逐条滚动；`RAME:INGEST` 标签行是最近写入的记忆单元回显——展示的是水合后的正文，不会把内部指针原样打印。
2. **任务卡片**：每执行一条命令生成一张卡片，包含命令行、完整输出与成功/失败状态；支持**重新执行**与一键**清理已完成任务**。
3. **快捷命令按钮**：`rmem status`、`rmem doctor`、`rmem recent`，以及「更多诊断命令」下拉中的 `rolling-memory check` 与 `rolling-memory sync prune`（只读预演）。
4. **流控制**：可暂停/继续实时流、切换自动滚动、按 `ALL / HOOK / RAME` 过滤事件来源。

## 3. 常用命令对照表

| 命令 | 作用 | 在哪里执行 |
|---|---|---|
| `rmem status --json` | 引擎状态：版本、运行模式、金库路径与规模 | 终端（按钮） |
| `rmem doctor --json` | 自检：环境、宿主接线、金库健康 | 终端（按钮） |
| `rmem recent --limit 10 --json` | 最近写入的记忆单元（正文已水合） | 终端（按钮） |
| `rmem check --json` | 一致性检查：索引与协议契约 | 终端（下拉） |
| `rmem sync prune --json` | **回收与自愈预演**（只读）：内容完好 / 可重锚 / 可回收 / 源不可读计数 | 终端（下拉） |
| `rmem recall --cue "关键词" --json` | 手动检索一次，排查「为什么没命中」 | 系统终端 |
| `rmem sync watch --pause / --resume / --step` | 后台扫描与历史指针索引回填控制 | L2 会话记录页按钮 |
| `rmem recover --passes 10 --budget-sec 60` | 从本地转录窗口重建金库：只做增量扫描，不做回收、自愈与清理（`--limit` 限定每轮条数） | 系统终端 |
| `rmem sync prune --apply --yes` | **执行回收与自愈**：回收确证过时的单元、重锚坐标位移的指针，写入可审计回执 | 记忆总览 → 「回收与自愈」入口 |
| `rmem eval --suite atm …` | 冻结基准评测 | 评测实验室 |

> 终端只挂载受支持的只读诊断命令；凡会删除或改写数据的操作（回收执行、删除记忆单元、卸载目录、系统更新）一律走对应页面的显式确认入口，不在终端提供一键执行。

## 4. 安全边界

- **白名单执行**：终端只执行受支持的命令键，未知命令不会传给系统 shell；子进程环境会剥离云端凭据，本地模式（`local_plain`）零外呼。
- **回显纪律**：所有回显与输出一律展示水合后的正文；无法解析来源的行显示「来源缺口」占位，绝不显示内部指针原文。
- **结果可追溯**：命令输出保留在任务卡片中，可随时重新执行；破坏性维护命令的回执文件路径会随结果一并给出（存档在 `~/.local/state/rolling-memory/`）。
- **与页面协同**：终端与各页面共享同一份本地金库与同一套引擎实现；在任一侧的改动都会在另一侧如实呈现（例如执行回收后，环境体检计数会自动刷新）。
